# project-AIRIS-v2

> **체형·시나리오 적응형 에어게이트: 입자 시뮬레이션과 블랙박스 최적화로 먼지 제거에 최적인 자세를 찾는다**

---

## 1. 프로젝트 개요

### 한 줄 요약

에어게이트를 통과하는 사람의 **체형과 시나리오**(일반 성인, 임산부, 휠체어 사용자)에 맞춰 먼지가 가장 잘 제거되는 **자세**를 GPU 입자 시뮬레이션과 블랙박스 최적화로 찾아내고, 그 결과를 학습한 모델로 게이트 앞에서 실시간 안내하는 **체형 적응형 에어게이트 시스템**을 개발한다. 노즐 설정의 동적 조절은 확장 항목으로 두고 별도 논의한다 (12절).

### 에어게이트란

에어게이트(에어샤워)는 클린룸, 식품·제약 공장, 병원 무균 구역 입구에 설치되어 사람이 통과하는 동안 고속 공기 제트로 옷과 몸의 먼지를 털어내는 장치다. 벽면에 노즐 수십 개가 고정되어 있고, 표준 풍속은 약 25 m/s, 분사 시간은 15~45초다. 최근에는 미세먼지 대응으로 아파트 현관, 학교, 어린이집 같은 생활 공간에도 보급되고 있다. 현재의 장치는 노즐이 평균 성인 기준으로 고정되어 있고 안내는 "팔을 들고 천천히 도세요" 한 문장이다. 이 프로젝트는 그 관계를 뒤집어 **장치가 사람에게 맞추는** 구조를 만든다.

### 무엇을 구현하는가

완성된 시스템은 다음 순서로 동작한다. 각 단계가 하나의 구현 항목이다.

**1. 게이트 앞: 체형 추정과 시나리오 선택**

사람이 게이트 앞에 서면 카메라 한 대가 촬영하고, YOLO11-pose로 관절 키포인트 17개를 추출한다. 키포인트에서 키, 어깨 너비, 몸통 두께, 팔 길이, 다리 길이의 5개 체형 값을 추정한다. 카메라 거리 보정은 바닥의 기준 마커로 한다. 시나리오는 화면에서 사용자가 직접 고른다. 임산부 여부를 영상으로 판별하지 않는 것은 정확도와 윤리 양쪽의 이유다. v1의 웹캠 입력과 사람 검출 코드를 재사용한다.

**2. 실시간 응답: 회귀 모델**

체형 5개와 시나리오를 입력받아 자세 7개 변수를 밀리초 안에 출력하는 scikit-learn 회귀 모델이다. 이 모델의 학습 데이터는 사람이 라벨링한 것이 아니라 아래 3~5번의 오프라인 최적화가 생성한다. 게이트 앞에서 최적화를 직접 돌리면 수 초에서 수십 초가 걸리므로, 미리 계산한 결과를 일반화해 두는 것이 이 모델의 역할이다. 출력된 자세는 3D 마네킹으로 화면에 그려 안내한다.

**3. 먼지 제거 시뮬레이터: 마네킹과 제트**

시스템의 핵심은 "이 체형의 사람이 이 자세를 취했을 때 먼지가 얼마나 제거되는가"를 계산하는 시뮬레이터다.

마네킹은 관절 17개를 기준으로 캡슐(원통 + 반구) 조합으로 만든다. 체형 값이 캡슐의 길이와 반지름을, 자세 값이 관절 각도를 통해 캡슐의 위치와 방향을 정한다. 휠체어 시나리오는 골반을 좌석 높이에 두고 하체를 앉은 자세로 고정하며 휠체어 프레임을 가림 형상으로 추가한다. 캡슐 표면은 패치 수백~수천 개로 나누어 각 패치가 위치, 법선, 면적, 부위(머리·몸통 앞·몸통 뒤·팔·다리)를 갖는다.

노즐은 업계 표준 배치를 따라 **고정**한다. 양쪽 벽면에 높이 3~4단으로 배치하고, 측면 노즐은 몸 쪽으로 20~30도 기울인다. 배치는 설정 파일에 두어 다른 게이트 형상으로 바꿀 수 있게 한다. 노즐 제트는 자유 제트 실험식으로 모델링한다. 출구부터 노즐 지름의 약 6배까지는 출구 속도를 유지하고, 이후 중심 속도는 거리에 반비례해 감쇠하며 단면은 가우시안이다. 표면 근처에서는 충돌 제트의 벽면 전단 분포로 치환하는 보정을 옵션으로 둔다. 펄스 분사도 옵션이다.

**4. 먼지 제거 시뮬레이터: 입자 계산**

패치 위에 먼지 입자 2만 개를 면적 비례로 뿌린다. 입자마다 지름(로그 정규, 중앙값 20µm)과 임계 전단력(로그 정규)을 부여한다. 임계 전단력의 분포가 옷감을 근사한다. 섬유 사이에 박힌 입자는 임계값이 높고, 표면에 얹힌 입자는 낮다. 매 시간 단계마다 각 입자가 놓인 곳의 벽면 전단력이 임계값을 넘으면 이탈하고, 이탈한 입자는 항력을 받아 기류를 따라 움직이며, 몸에 다시 닿으면 재부착 확률로 붙거나 튕기고, 부스 밖으로 나가면 제거로 확정한다. 3초를 2ms 간격으로 1,500스텝 계산한다.

이 계산을 Taichi로 GPU 커널로 작성하되, 처음부터 **후보 100개를 한 커널에서 동시에** 처리하는 배치 구조로 만든다. 최적화 한 세대가 GPU 호출 한 번이 되어 세대당 수십~수백 ms에 끝난다. 같은 입력이면 같은 점수가 나오도록 시드를 고정한다. 물리 상수(감쇠 계수, 임계 전단 분포, 재부착 확률 등)는 설정 파일 한 곳에 모아 민감도 실험과 실측 보정이 가능하게 한다.

입자판과 별도로 입자 없이 패치별 유효 풍속만으로 제거율을 근사하는 numpy 기준선도 만든다. 입자판이 완성되기 전에 최적화 파이프라인을 끝까지 돌리는 대체재이자, 입자판이 이상하게 동작할 때의 비교 대상이다.

**5. 최적화: 시나리오별 자세 탐색**

시뮬레이터가 돌려주는 점수를 목적 함수로 CMA-ES를 돌린다. 점수는 부위별 제거율의 가중합에서 자세 불편도 페널티를 뺀 값이다. 결정 변수는 자세 7개(어깨 벌림·굽힘, 팔꿈치, 상체 기울기·회전, 고관절, 무릎)다. 시나리오별 제약은 설정 파일로 둔다. 임산부는 상체 굽힘 범위를 좁히고 페널티를 키운다. 휠체어는 고관절과 무릎을 90도로 고정하고 몸통 회전을 ±45도로 제한한다. 변수가 7개라 시나리오당 2~3천 회 평가면 수렴하며, 시드 5개로 반복해 수렴을 확인한다.

**6. 데이터셋 생성과 학습**

인체 측정 통계에서 체형 1,500개를 샘플링하고 시나리오 3개와 조합해 4,500회 최적화를 돌린다. 결과를 (체형, 시나리오, 최적 자세, 점수) 한 행으로 저장한다. 이 데이터셋으로 2번의 회귀 모델을 학습한다. 평가는 예측값의 수치 오차가 아니라 **예측한 자세를 시뮬레이터에 넣었을 때의 점수가 직접 최적화한 점수의 몇 %인가**로 한다. 이 계산은 RTX 4090급 클라우드 GPU에서 30~80시간이 걸린다.

**7. 검증**

결론의 신뢰도를 세 겹으로 확보한다. 첫째, "팔을 들면 겨드랑이 제거율이 오른다" 같은 정성 검증을 자동 테스트로 만들어 병합 게이트로 쓴다. 둘째, 물리 상수 5개를 각각 0.5~2배로 바꿔 최적화를 반복하고 어떤 결론이 상수와 무관하게 유지되는지 판정한다. 셋째, Taichi-LBM3D를 확장한 격자 볼츠만 유체 솔버로 부스 안 기류를 실제로 계산해 상위 후보를 재평가한다. 이 솔버는 1회 수 초라 최적화 루프에는 못 쓰지만, 해석적 제트 모델이 놓치는 몸 주변 회절 기류와 노즐 간 간섭을 잡아준다.

### 핵심 설계 원칙

**최적화와 학습의 역할을 분리한다.** 정답 라벨은 없지만 시뮬레이터가 점수를 주므로 최적화는 가능하고, 최적화 결과가 학습 라벨이 된다. 강화학습은 쓰지 않는다. 찾는 것이 정적 자세라 순차 의사결정 문제가 아니고, 블랙박스 최적화가 더 단순하고 확실하다. 머신러닝은 "새로운 체형에 즉시 답하기"라는 실제로 필요한 자리에만 쓴다.

**현실성은 계산으로 사고, 개발 시간은 아낀다.** 정밀 인체 메시나 옷감 펄럭임 시뮬레이션은 개발 부담이 크면서 기류 모델 오차에 묻힌다. 대신 입자 수와 시뮬레이션 길이처럼 GPU 시간으로 해결되는 축에 자원을 쓴다. 6주 중 개발은 2주, 계산과 실험에 3~4주를 배정한다.

**절대값이 아니라 순위를 주장한다.** 시뮬레이터 상수가 실측 보정되지 않았으므로 "제거율 87%" 같은 절대값은 주장하지 않는다. "기준 자세 대비 개선율"과 "상수 선택과 무관하게 유지되는 결론"을 결과로 제시한다.

### 산출물

- 시나리오별 최적 자세와 고정 노즐 + 일률 안내 대비 개선 폭.
- 재사용 가능한 GPU 입자 기반 에어게이트 시뮬레이터. 노즐 배치 설계나 분사 패턴 연구로 확장 가능하다.
- 체형 → 자세 회귀 모델과 데이터셋.
- 카메라 한 대로 동작하는 실시간 안내 데모.

### v1과의 관계

이전 프로젝트 project-AIRIS-MVP는 생체·환경·시설 맥락으로 위험도를 추정해 게이트 세기를 조절하는 상황 판단 시스템이었다. v2는 물리적으로 먼지를 가장 잘 제거하는 자세를 찾는 최적화 시스템으로 주제를 바꾼다. v1에서 가져오는 것은 웹캠 입력, YOLO 사람 검출, Streamlit 대시보드 틀이며, 생체 정보와 시설 맥락 모듈은 사용하지 않는다.

## 2. 연구 질문과 가설

### 주 질문

> 체형과 시나리오를 고려해 자세를 개인화하면, 일률적인 안내보다 먼지 제거율이 유의미하게 높아지는가?

### 하위 질문

| 번호 | 질문 | 검증 실험 |
|---|---|---|
| Q1 | 자세를 최적화하면 기본 자세와 업계 권장 자세 대비 제거율이 얼마나 오르는가? | E4 |
| Q2 | 시나리오별 최적 자세는 서로 어떻게 다른가? 체형에 따라 얼마나 달라지는가? | E4 |
| Q3 | 최적화 결과가 물리 상수 선택에 얼마나 민감한가? 순위가 안정적인가? | E3 |
| Q4 | 최적화 결과를 학습한 모델이 새로운 체형에 일반화되는가? | E5 |
| Q5 | 저비용 시뮬레이터의 결론이 고정밀 유체 시뮬레이션에서도 유지되는가? | E6 |

### 가설

- H1: 자세 최적화만으로 업계 권장 자세 대비 제거율이 10% 이상 오른다.
- H2: 큰 기하학적 효과(팔 들기, 몸 방향)는 물리 상수를 바꿔도 순위가 유지된다.
- H3: 회귀 모델이 예측한 자세는 개인별로 직접 최적화한 점수의 95% 이상을 달성한다.

## 3. 문제 정의

### 입력

| 항목 | 표현 | 출처 |
|---|---|---|
| 체형 | 키, 어깨 너비, 몸통 두께, 팔 길이, 다리 길이 (5개 실수) | 포즈 추정 또는 샘플링 |
| 시나리오 | `default`, `pregnant`, `wheelchair` | 사용자 선택 |
| 노즐 배치 | 노즐 M개의 위치, 방향, 세기 | 설정 파일 (고정) |

### 결정 변수

| 항목 | 표현 | 범위 |
|---|---|---|
| 자세 | 어깨 벌림·굽힘, 팔꿈치, 상체 기울기·회전, 고관절, 무릎 (7개 각도) | 시나리오별 상하한. 휠체어는 하체 고정 |

### 목적 함수

```
score = Σ_부위 w_부위 · 제거율_부위  −  λ · 불편도
불편도 = Σ_관절 c_관절 · |각도 − 기본각도| / 범위
```

부위 가중치와 불편도 가중치는 시나리오별로 다르다. 임산부는 상체 굽힘에, 휠체어 사용자는 팔 높이에 큰 페널티를 둔다.

### 제약

- 시나리오별 관절 각도 범위 (`configs/scenarios.yaml`)
- 시나리오별 고정 자세 (휠체어: 고관절·무릎 90도)

### 왜 강화학습이 아닌가

찾는 것이 **통과 중 한 번 정해지는 정적 자세**이므로 순차 의사결정 문제가 아니다. 상태 전이가 없는 "입력 → 점수" 함수의 최적화이고, 이 경우 블랙박스 최적화(CMA-ES)가 강화학습보다 단순하고 확실하다. 머신러닝은 최적화 결과를 새로운 체형에 **일반화**하는 회귀 단계에서 실제로 필요한 자리에 들어간다.

## 4. 전체 파이프라인

```
[오프라인: 최적화]
  체형·시나리오 샘플 수천 개  +  고정 노즐 배치
        ↓
  입자 시뮬레이터 (Taichi GPU, 후보 100개 배치 평가)
        ↓
  CMA-ES → 체형·시나리오별 최적 자세
        ↓
  (체형, 시나리오, 최적 자세, 점수) 데이터셋

[학습]
  데이터셋 → 회귀 모델 (scikit-learn)
  입력: 체형 5개 + 시나리오 → 출력: 자세 7개

[실시간: 게이트 앞]
  카메라 → 포즈 추정 (YOLO11-pose) → 체형 추정 + 시나리오 선택
        ↓
  회귀 모델 → 자세 안내 (3D 마네킹 화면)

[검증]
  패치 기준선 비교 · 물리 상수 민감도 · LBM 유체 솔버 재평가
```

## 5. 개발 항목

### 5.1 마네킹 모델 (`airis/sim/body.py`, 담당 B)

- 관절 17개를 기준으로 몸을 **캡슐(원통 + 반구)** 조합으로 표현한다. 몸통은 타원 캡슐, 팔다리는 원형 캡슐, 머리는 구.
- 체형 파라미터가 캡슐의 길이와 반지름을, 자세 파라미터가 관절 각도를 통해 캡슐의 위치와 방향을 결정한다 (순기구학).
- 캡슐 표면을 **패치** 수백~수천 개로 샘플링한다. 패치마다 위치, 바깥 법선, 면적, 소속 부위를 갖는다.
- 휠체어 시나리오는 좌석 높이에 골반을 두고 하체를 앉은 자세로 고정한다. 휠체어 프레임은 가림용 캡슐로 추가한다.
- SMPL 같은 정밀 메시는 쓰지 않는다. 기류 모델 오차가 더 크기 때문에 얻는 것이 없다.

### 5.2 노즐 배치와 제트 유동 모델 (`configs/nozzles.yaml`, `airis/sim/jet.py`, 담당 B)

- **고정 노즐 배치**: 업계 표준을 따라 양쪽 벽면에 높이 3~4단, 측면 노즐은 몸 쪽으로 20~30도 경사. 설정 파일로 정의하고 최적화 대상이 아니다.
- **자유 제트**: 노즐 출구부터 포텐셜 코어(노즐 지름의 약 6배)까지는 출구 속도 유지, 이후 중심 속도는 거리에 반비례해 감쇠, 단면은 가우시안. 확산 반각 약 12도.
- **충돌 제트 보정 (옵션)**: 표면 근처에서는 자유 제트 대신 벽면 전단 분포로 치환한다. 정체점은 전단력이 0에 가깝고 실제로 강한 곳은 중심에서 제트 반지름 2~3배 떨어진 고리 영역이다. 노즐이 고정이라 필수는 아니지만, 몸통 회전과 노즐 거리에 대한 결론에 영향을 주므로 2주차 옵션으로 둔다.
- **펄스 제트 (옵션)**: 주기와 듀티로 on/off 변조.
- 노즐 M개의 속도장을 합산한다. 난류 제트의 상호작용은 무시하며, 이 오차는 E6에서 확인한다.
- 모든 상수는 `configs/physics.yaml` 한 곳에 둔다.

### 5.3 입자 시뮬레이터 (`airis/sim/particles.py`, 담당 A)

프로젝트의 핵심. Taichi로 GPU 커널을 작성한다.

- **입자 초기화**: 후보 하나당 입자 2만 개를 패치 위에 면적 비례로 뿌린다. 입자마다 지름(로그 정규 분포, 중앙값 20µm), 임계 전단력(로그 정규 분포), 부착 상태, 소속 부위를 갖는다.
- **부착 → 이탈 판정**: 입자가 놓인 패치의 벽면 전단력이 그 입자의 임계값을 넘으면 이탈한다. 임계값 분포로 옷감의 거칠기와 섬유 사이에 박힌 입자를 근사한다 (rock'n'roll 모델의 단순화).
- **이탈 후 운동**: 속도장에서 항력(Schiller-Naumann)을 받아 적분. 캡슐과 충돌하면 재부착 확률로 다시 붙거나 튕긴다. 부스 밖으로 나가면 제거 확정.
- **배치 실행**: 후보 B개 × 입자 N개를 한 커널에서 처리한다. CMA-ES 한 세대(후보 100개)가 한 번의 GPU 호출이다. 후보 간 상태가 섞이지 않는지 테스트로 보장한다.
- **결정론**: 시드 고정. 같은 입력이면 같은 점수.
- **성능 목표**: 입자 2만 × 후보 100, 3초 시뮬레이션(1,500스텝)을 수십 ms~수백 ms 안에.
- **시각화 덤프**: 프레임별 입자 위치와 부착 상태를 npz로 저장 (최적화 중에는 끔).

### 5.4 패치 기준선 (`airis/sim/patch_baseline.py`, 담당 D)

- 입자 없이 패치별 유효 풍속만으로 제거율을 계산하는 numpy 평가기. 밀리초 단위.
- 유효 풍속 = 제트 속도 × 법선 각도 계수 × 가림 여부(캡슐 레이캐스팅).
- 역할: (1) 입자판 완성 전까지 최적화 파이프라인을 끝까지 돌리는 대체재, (2) 입자판 디버깅 시 비교 대상, (3) 입자판이 늦어질 때의 보험.

### 5.5 최적화 (`airis/optimize/`, 담당 C)

- **알고리즘**: CMA-ES (`cma` 패키지). 변수 7개, 미분 불가, 시뮬레이터가 빠르므로 적합.
- **인코딩**: 자세 변수 중 시나리오의 고정 자세를 제외한 것을 `pose_bounds`로 [-1, 1] 정규화.
- **세대 크기**: 100. 배치 평가 한 번이 한 세대.
- **종료**: 3천 회 평가 또는 30세대 정체.
- **로그**: 실험 ID, 커밋 해시, 설정 파일 해시, 세대별 최고점, 최종 자세를 `outputs/<exp_id>/`에 저장.
- **데이터셋 생성**: 체형 1,500개 × 시나리오 3개 = 4,500회 최적화. 체형은 인체 측정 통계 기반 정규분포에서 샘플링. 재개 가능하게 설계.

### 5.6 회귀 모델 (`airis/model/`, 담당 C)

- 입력: 체형 5개 + 시나리오 원핫 3개. 출력: 자세 7개.
- scikit-learn MLPRegressor와 HistGradientBoostingRegressor를 비교. 5-fold 교차검증.
- 평가는 출력값의 오차가 아니라 **예측한 자세를 시뮬레이터에 넣었을 때의 점수**로 한다 (E5).

### 5.7 실시간 파이프라인 (`airis/realtime/`, `airis/viz/`, 담당 E)

- v1의 웹캠 입력과 YOLO 사람 검출을 재사용하고, YOLO11-pose로 키포인트 17개를 추출한다.
- 키포인트에서 키, 어깨 너비, 팔 길이를 추정한다. 카메라 거리 보정은 기준 물체 또는 알려진 키 입력으로 한다.
- 시나리오는 화면에서 사용자가 선택한다.
- 회귀 모델의 출력을 3D 마네킹으로 그려 안내한다.
- 개발용 3D 뷰(matplotlib)와 발표용 대시보드(Streamlit + plotly)를 나눈다.

### 5.8 LBM 검증 파이프라인 (`validation/lbm/`, 담당 D)

- Taichi-LBM3D를 확장해 부스 안 기류를 격자 볼츠만 방법으로 계산한다. 격자 128³, 마네킹은 침지 경계로 넣는다.
- 노즐은 출구 경계 조건으로, 부스 벽과 배기구도 경계로 넣는다.
- 1회 2~10초라 최적화 루프에는 못 쓴다. E6에서 상위 후보 재평가에만 쓴다.

## 6. 실험 계획

### E1. 정성 검증 (1주차, D)

시뮬레이터가 최소한 방향은 맞는지 확인하는 자동 테스트. 병합 게이트로 쓴다.

| 테스트 | 기대 결과 |
|---|---|
| 팔을 들면 | 겨드랑이·옆구리 제거율 상승 |
| 노즐을 등지면 | 정면 제거율 하락 |
| 노즐에 가까이 서면 | 제거율 상승 |
| 노즐 세기 0 | 제거율 0 |
| 같은 입력 두 번 | 같은 점수 |

### E2. 패치판 vs 입자판 일치도 (2주차, D)

- 무작위 자세 500개를 두 평가기로 평가하고 점수의 순위 상관(Spearman)을 본다.
- 0.8 이상이면 패치판을 대체재로 신뢰. 낮으면 어느 쪽이 틀렸는지 시각화로 추적.

### E3. 물리 상수 민감도 (3주차, C + D)

- 대상 상수: 임계 전단 중앙값, 임계 전단 분산, 제트 감쇠 상수, 재부착 확률, 입자 크기 중앙값.
- 각 상수를 기준값의 0.5, 0.75, 1, 1.5, 2배로 바꿔 시나리오 3개를 최적화.
- 지표: 상수 변화에 따른 **최적 자세의 변화량**과 **상위 10개 후보의 순위 안정성**.
- 결론: 순위가 안정적인 결론(예: 팔 들기)은 신뢰하고, 불안정한 결론은 "상수 의존"으로 표시한다. 실측이 필요한 상수 목록이 여기서 나온다.

### E4. 시나리오별 자세 최적화와 기준선 비교 (3주차, C)

핵심 실험. 시나리오 3개 × 시드 5개.

| 조건 | 자세 | 의미 |
|---|---|---|
| B0 | 기본 자세 (팔 내림, 정면) | 안내 없이 통과할 때 |
| B1 | 업계 권장 (팔 들고 정면) | 현재 최선의 안내 |
| C1 | 최적화 | 제안 방식 |

- 지표: 총 제거율, 부위별 제거율, 불편도, B0·B1 대비 상대 개선율.
- 시나리오별 최적 자세를 3D로 그려 비교한다 (Q2).
- 체형을 바꿔가며 최적 자세가 어떻게 이동하는지 본다 (Q2).
- 시드 5개의 결과 분산으로 최적화 수렴 여부를 확인한다.

### E5. 일반화 (4~5주차, C)

- 데이터셋 4,500행으로 회귀 모델 학습. 홀드아웃 체형 300개.
- 홀드아웃 체형마다 (a) 회귀 예측 자세, (b) 직접 CMA-ES 최적화 자세를 시뮬레이터로 평가.
- 지표: **(a) 점수 / (b) 점수** 의 분포. 중앙값 0.95 이상이면 H3 채택.
- 추가: 포즈 추정에서 오는 체형 오차(±5%)를 넣었을 때 점수 하락폭.

### E6. LBM 검증 (5주차, D)

- 시나리오별로 E4의 C1 상위 10개 + B0 + B1을 LBM으로 재평가 (총 36케이스, 1~3시간).
- 지표: 입자판 점수와 LBM 점수의 순위 상관. B0·B1 대비 C1의 우위가 LBM에서도 유지되는가.
- 유지되면 결론의 신뢰도 확보. 안 되면 어느 물리 효과(몸 주변 회절, 노즐 간섭)가 원인인지 분석.

### 계산 예산

RTX 4090급 클라우드 3주 상시 (약 500 GPU시간, 25~40만 원). E3 20~40h, E4 5~10h, E5 데이터셋 30~80h, E6 30~60h. 변수가 7개라 예산에 여유가 크므로 남는 시간은 입자 수 확대(2만 → 10만)와 E6 케이스 확대에 쓴다.

## 11. 범위 밖과 한계

- **걷기·회전 동작**은 다루지 않는다. 정적 자세만 최적화한다.
- **옷의 펄럭임**(cloth 시뮬레이션)은 다루지 않는다. 부착력 분포로 근사한다.
- **노즐 하드웨어**는 만들지 않는다.
- **절대 제거율은 주장하지 않는다.** 시뮬레이터 상수가 실측으로 보정되지 않았으므로, 결과는 기준선 대비 상대 개선율로 제시한다.
- **미세한 각도 차이**(5도 수준)는 모델 오차에 묻힌다. 최적 자세는 점이 아니라 구간으로 제시한다.
- 시간이 되면 풍속계와 형광 분말 마네킹으로 물리 상수를 보정한다. 되지 않으면 E3의 민감도 결과로 대신한다.

## 12. 논의 사항: 노즐 동적 조절 확장

자세 최적화가 안정되면 노즐의 높이·방향·세기를 사람에 맞춰 조절하는 확장을 검토한다. 채택 여부는 3주차 E4 결과를 보고 결정한다. 채택 시 바뀌는 것은 다음과 같다.

### 결정 변수 추가

노즐 M개 × (높이 z, 좌우 각도, 상하 각도, 세기 0~1)이 추가되어 변수가 7개에서 30~40개로 늘어난다. 노즐의 벽면 위치는 고정하고 높이와 방향만 바꾼다. 시나리오별 제약에 노즐 높이 범위와 세기 상한이 추가된다 (임산부: 복부 정면 노즐 60% 이하, 휠체어: 노즐 높이 0.2~1.5m). `configs/scenarios.yaml`에 이 필드가 이미 있으며, `NozzleConfig` 타입도 최적화 벡터에서 채울 수 있게 되어 있다.

### 자세와 노즐의 동시 최적화

팔을 들면 겨드랑이 쪽 노즐이 유효해지고 몸을 돌리면 뒤쪽 노즐의 각도가 달라져야 하므로, 둘은 결합되어 있다. 따로 최적화하면 이 상호작용을 놓치므로 하나의 CMA-ES 벡터로 동시에 탐색한다. 변수가 늘어 시나리오당 평가 횟수가 1만 회로 늘고, 데이터셋 생성이 100~250 GPU시간으로 늘어난다.

### 실험 확장

E4에 조건 두 개가 추가된다.

| 조건 | 자세 | 노즐 | 의미 |
|---|---|---|---|
| C2 | 기본 자세 | 최적화 | 노즐 조정만의 효과 |
| C3 | 최적화 | 최적화 | 자세 + 노즐 |

Q1이 "자세만 / 노즐만 / 둘 다"로 확장되고, 회귀 모델의 출력에 노즐 설정이 추가된다.

### 충돌 제트 보정이 필수가 된다

노즐 각도를 최적화하면 "노즐을 몸 정면으로 조준"하는 답이 나오기 쉬운데, 실제로는 정체점의 전단력이 낮아 비스듬히 쏘는 쪽이 낫다. 5.2의 충돌 제트 보정 없이는 노즐 각도 결론이 현실과 반대로 나올 수 있으므로 옵션에서 필수로 올라간다.

### 열린 질문

- 노즐 방향을 실제로 바꾸려면 팬틸트 구동부가 필요하다. 시뮬레이션과 대시보드까지만 할지, 하드웨어 데모까지 갈지.
- 노즐 조절이 가능한 게이트는 현재 시장에 없다. 결과를 "신규 게이트 설계 제안"으로 낼지, "기존 게이트에서의 자세 안내"와 분리해서 낼지.
- 계산 예산이 3~4배 늘어난다. 6주 안에 자세 최적화의 E3~E6을 끝내고 남는 시간이 있는지.
