# 계획 데이터셋 구간표

계획 데이터셋 300행(체형 100개 × 사용자 유형 3개)을 노트북 여러 대가 나눠 만든다. **한 번에 구간 하나**를 맡아 돌리고, 끝나면 파일을 총괄에게 보낸 뒤 "대기"인 다음 구간을 받는다. 설치와 명령은 `docs/remote_run.md`에 있다.

- 이 표는 통합이 고친다. 구간을 시작하기 전에 `git pull`로 최신 표를 보고, **담당이 비어 있는 "대기" 구간**을 총괄에게 말한 뒤 시작한다(두 사람이 같은 구간을 돌리지 않게).
- 구간 하나(20행)는 기준 노트북 속도로 약 5~6시간이다(행 하나 약 2시간, 8개를 동시에 계산).
- 최종 갱신: 2026-10-10 22:50 (휠체어 W3·W4 완료·합침, 259행)

합계: 완료 259 / 300행 (선 자세 100, 임산부 100, 휠체어 59). 세 유형이 모두 있는 체형 59개. 남은 것은 휠체어 W1·W2(41행, 팀원 B)뿐이다.

상태의 뜻: **대기**(아무도 안 맡음) → **진행 중**(담당이 돌리는 중) → **받음**(파일을 총괄이 받음) → **합침**(전체 파일에 합쳐 검사까지 끝남).

## 담당 배정 (총괄 결정 2026-10-09)

| 담당 | 유형 | 맡는 순서 | 합계 |
|---|---|---|---|
| 총괄 (기준 노트북) | 선 자세 → 휠체어 뒤쪽 | D1 (완료) → W3 → W4 | 79 + 40행 |
| 팀원 A | 임산부 | P1 → P2 → P3 → P4 | 80행 |
| 팀원 B | 휠체어 | W1 → W2 | 41행 |

- 각자 자기 유형의 **번호가 작은 구간부터** 차례로 돌린다. 구간이 끝나면 파일을 총괄에게 보내고 다음 번호를 시작한다.
- 한 사람의 노트북이 많이 느리면 그 사람의 뒤쪽 구간(P4·W4)을 다른 사람이 가져간다. 그럴 때는 이 표를 먼저 고친다.
- 같은 행이 겹쳐도 결과가 틀리지는 않는다. 합칠 때 하나만 남기고, 버린 쪽의 계산 시간만 아깝다.

## 구간 하나를 돌리는 명령

```bash
python tools/remote/plan_share.py run --segment P4
```

끝나면 `status`가 알려 주는 파일(`outputs/remote_share/plan_dataset_n9_P4.parquet`)을 총괄에게 보낸다. 다 끝나기 전에 그만둬야 하면 `stop --yes` 뒤 그때까지 저장된 파일을 보내고, 어디까지 했는지(`status`의 "저장된 행")를 알려 준다. 남은 부분은 다른 사람이 같은 구간 이름으로 이어 돌릴 수 있다(받은 파일을 `--seed-file`로 준다).

## 총괄·통합이 할 일 (구간이 끝날 때마다)

1. 받은 파일을 기준 노트북의 `outputs/remote_share/`에 둔다.
2. 구간별 완료 행 수를 본다.

```bash
python tools/remote/plan_share.py segments ../airis-v2-e4bound/data/datasets/plan_dataset_n9.parquet outputs/remote_share/plan_dataset_n9_P4.parquet
```

3. 이 표의 상태·받은 행·합계를 고쳐 PR로 올린다.
4. 세 유형이 모두 있는 체형이 50개가 되면(또는 전부 끝나면) `merge`로 합치고, 합친 파일이 `airis.model.plan_data.read_plan_dataset`으로 읽히는지 확인한 뒤 F에 넘긴다.
