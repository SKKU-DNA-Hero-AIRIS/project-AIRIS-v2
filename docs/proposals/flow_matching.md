# 제안: 조건부 Flow Matching으로 체형별 자세·계획 추천

> 2026-09-28 작성, 2026-09-29 통합 검토(#78) 반영 · 제안 문서 (코드 변경 없음). 기준: main `2789474` (#80 세기·시간 확장, #82 계획 대칭 규칙 병합 후). 구현: #79, #81.

체형 → 출력(자세 또는 계획) 모델 자리에 조건부 flow matching을 두고, 샘플 여러 개를 시뮬레이터로 재채점해 고른다. 최적 출력이 봉우리 여러 개로 갈리는 구조라 평균 회귀보다 분포 모델이 맞고, 시뮬레이터·CMA-ES·데이터셋 파이프라인은 그대로 쓴다.

**현재 판단 (#81 메시판 E5):** 자세 7개만 예측하는 지금 문제에서는 같은 재채점 횟수의 kNN이 flow보다 높다. flow의 가치는 (a) 체형당 후보 여러 개(`--candidate-k`)로 학습했을 때와 (b) 출력이 21차원으로 늘어나는 계획(Plan)에서 다시 판단한다. 채택 여부는 5절의 기준으로 정한다.

---

## 1. 왜 필요한가

### 1.1 다봉 구조

회귀 모델은 봉우리 두 개의 평균을 내서, 점수가 낮거나 부스 밖인 자세를 낼 수 있다. 메시판 데이터셋(300행, `docs/experiments.md`)에서 확인된 구조는 다음과 같다.

| 관찰 | 수치 | 회귀 모델에 주는 문제 |
|---|---|---|
| 팔 벌림 두 봉우리 | 150~180°(만세) 272행, 0~60°(팔 내림) 28행, 60~150° 0행 | 평균 90° 근처 = 데이터에 없는 자세, 부스 밖일 수 있음 |
| yaw 대칭 | +θ ≡ −θ, θ ≡ 180° − θ (0.6533 vs 0.6534) | 접기 없이 학습하면 평균이 0° 또는 90°로 붕괴 |
| 체형에 따른 봉우리 전환 | wheelchair 키 1.45–1.60 m 만세 25%, 1.70–1.80 m 97% | 경계 근처에서 두 봉우리 사이 값 출력 |
| 천장 경계 | 키 1.856 m부터 만세(B2) 불가, 1.86 m는 벌림 163°, 1.93 m는 팔 내림 | 경계 너머에서 불가 자세 출력 |

### 1.2 현재 스텁이 이미 강하다 (통합 검토, main `714b63c`, 메시 몸, 2,000/m² 재채점)

| 항목 | default | pregnant | wheelchair |
|---|---|---|---|
| 만세 봉우리 비율 | 99% | 98% | 75% |
| 체형만으로 봉우리 분류 (5-fold CV) | 한 봉우리 | 한 봉우리 | 0.88~0.90 |
| 봉우리 오분류 시 손실 (중앙값) | 2.8% | 5.3% | 2.5~3.5% |
| **스텁(고정 후보 2개 + 재채점) 점수 비율 중앙값** | 0.999 | 0.996 | 0.998 |
| 스텁 점수 비율 하위 5% | 0.900 | 0.956 | 0.917 |
| 점수 비율 0.95 미만 체형 | 11% | 4% | 16% |

- 봉우리 안에서 자세의 체형 의존성은 약하다 (선 자세 CV R² 0.2~0.5, wheelchair 만세 봉우리는 0 이하).
- 스텁이 떨어지는 곳은 키 1.45~1.55 m와 wheelchair 팔 내림 구간이다. 모델이 이겨야 할 곳은 평균이 아니라 **이 꼬리**다.

### 1.3 출력이 계획(21차원)으로 늘어난다 — 분포 모델이 필요한 본래 이유

총괄 결정(`docs/plan_extension.md`)으로 최적화 대상이 자세 7개에서 **자세 순서 + 분사 시간 + 구역별 세기**로 넓어졌다.

| 묶음 | 변수 | 개수 |
|---|---|---|
| 자세 순서 | 2단계 × 자세 7개 | 14 |
| 시간 | 총 시간 5~20 s, 단계 분할 | 2 |
| 세기 | 몸 기준 구역 5개 (가슴 쪽 벽 하·상, 등 쪽 벽 하·상, 천장) | 5 |

- 자세 봉우리마다 맞는 세기 배분이 다를 수 있다. 그러면 좋은 계획은 (자세, 세기) 짝으로 존재하고, 변수별로 따로 평균을 내면 짝이 깨진다. #81 테스트가 합성 데이터에서 flow가 이 짝을 유지하는 것을 확인했다(실제 계획 데이터로는 E7에서 확인).
- 고정 후보표(스텁)는 21차원에서 체형마다 맞출 수 없고, 가까운 체형의 계획(kNN)도 시간·세기 조합이 그대로 맞는다는 보장이 없다.
- 게이트 앞에서 21차원 CMA-ES를 돌리면 1만 회 × 약 80 ms ≈ 13분이라 실시간이 안 된다.

→ 결합 분포를 한 번에 학습하고 재채점으로 고르는 구조가 이 확장에서 가장 필요하다.

## 2. 어디에 넣나

바뀌는 곳은 **후보 저장, 학습 모델, 추천 단계** 세 곳이다 (`*` 표시).

```
[① 오프라인: 데이터셋 생성]
  체형·시나리오 샘플  →  시뮬레이터 (패치판, 기존)  →  CMA-ES + 후보 저장*
  (메시 체형 분포 × 3)    evaluate / evaluate_plan     (최고점 2% 이내 후보 여러 개)
                                                              ↓
[② 학습]                                           조건부 flow matching*
                                                    p(출력 | 체형, 시나리오)
                                                    출력 = 자세(7) 또는 계획(21)
                                                              ↓ 학습된 모델
[③ 게이트 앞: 실시간 추천]
  체형 추정            →  후보 샘플링·재채점*        →  안내·장비 제어
  (카메라 또는 mmWave)     샘플 + 고정 후보를 함께 채점     자세(단계별), 구역 세기, 시간
```

체형 입력은 카메라(v2)든 mmWave(추가 계획)든 같은 `BodyParams` 인터페이스로 들어온다.

## 3. 설계안

모델은 **출력 길이에 묶이지 않는** 작은 MLP 벡터장 하나다. 출력 공간이 키 순서·범위·시나리오별 마스크를 정하고, 학습·샘플링 코드는 공통이다 (#81 `VectorSpace`).

| 항목 | 내용 |
|---|---|
| 조건 | 체형 5개 + 시나리오 원핫 (mmWave 계획이면 몸무게 등 추가) |
| 출력 공간 | 임의 길이 벡터 + 시나리오별 마스크. `PoseSpace`(자세 7) · `PlanSpace`(계획 21, 키 순서는 `interfaces.md` 계획 벡터 규약) |
| 마스크 | 시나리오가 고정한 변수는 손실에서 뺀다 (휠체어 hip·knee는 모든 단계에서 0) |
| 대칭 | 자세: yaw 0~90°로 접음. 계획: 좌우 거울·앞뒤 등가를 **계획 전체에 함께** 적용해 1단계 yaw만 0~90° (`00_common.md` 4.7, #82) |
| 학습 목표 | conditional flow matching: x_t = (1 − t)·x_0 + t·x_1, 목표 속도 x_1 − x_0를 마스크 MSE로 회귀. (체형 × 시나리오) 묶음마다 가중치 합 1 |
| 데이터 | 체형마다 정답 1개면 사실상 회귀와 같다. CMA-ES 후보 중 최고점 2% 이내를 여러 개 저장(`--candidate-k`, `cand_pose_*` / `cand_plan_*`) |
| 추론 | 샘플 n개 + 고정 후보(스텁)를 **함께** 재채점 → 최고. 모델이 스텁보다 나빠지지 않는다 (`extra_candidates`) |
| 계약 | `predict_pose(body, scenario) -> PoseParams` (유지), `predict_plan(body, scenario) -> Plan` (추가) |
| 산출물 | `data/models/pose_flow.pt`, `data/models/plan_flow.pt`. `nozzle_layout_hash`·`physics_hash`·학습 커밋·`space_kind` 저장, 다르면 경고 |
| 시간 | ODE 16스텝 수 ms. 재채점은 자세 1회 약 40 ms, 계획 1회 약 80 ms → 계획 16개 약 1.3초 |

계획 출력은 장비로 나가기 전에 C의 `PlanEncoder.clip_plan`(총 풍량 한도 보수, 임산부 가슴 쪽 세기 ≤ 0.6, yaw 범위 감기)을 거쳐야 한다.

## 4. 오해하기 쉬운 점

flow matching이 도움이 되는 이유는 다봉·결합 분포를 다루기 때문이지, 바람의 경로를 학습하기 때문이 아니다.

- **flow는 공기 흐름이 아니다.** flow matching의 flow는 노이즈 분포를 출력 분포로 옮기는 벡터장이다. 노즐에서 나온 바람의 경로는 `airis/sim/jet.py`의 자유 제트 식이 계산한다.
- **이상적인 바람 도달 위치는 미리 정해져 있지 않다.** 바람이 몸의 어디에 어떤 각도로 닿는지는 자세가 정하고, 그 자세를 찾는 것이 CMA-ES다. 제거 여부는 도달 위치가 아니라 표면 전단력이 정한다.
- **회귀보다 데이터를 덜 쓰지 않는다.** 같은 CMA-ES 데이터셋이 필요하고, 보통은 더 많이 필요하다.
- **재채점이 성능의 대부분을 만든다.** #81에서 재채점 없는 flow1은 평균 회귀보다 낫지 않았다. 모델의 역할은 "좋은 후보를 적은 횟수로 제안하는 것"이다.
- **최적화를 대체하지 않는다.** 라벨은 여전히 시뮬레이터 + CMA-ES가 만든다.

## 5. 검증 계획

### 5.1 지표와 채택 기준

점수 비율 = (예측 출력의 시뮬레이터 점수) / (그 체형을 직접 CMA-ES로 최적화한 점수).

- **채택 기준: 하위 5% 점수 비율과 0.95 미만 체형 비율이 스텁·kNN보다 나을 것.** 중앙값 0.95(README H3)는 스텁이 이미 넘으므로(0.996~0.999) 변별력이 없다. 1.2절의 스텁 수치가 넘어야 할 기준선이다.
- **재채점 횟수를 같게 맞춰 비교한다.** 재채점이 성능을 좌우하므로 횟수가 다른 방법끼리는 비교하지 않는다.
- **경계 구간을 따로 집계한다:** wheelchair 키 1.45~1.60 m, 선 자세 키 1.83 m 이상.
- **holdout은 체형 5-fold로 전 체형을 돌린다.** holdout 20체형이면 하위 5%와 0.95 미만 비율이 1~2체형으로 정해져 방법 간 차이를 가를 수 없다.
- 추가: 체형에 ±5% 오차를 넣었을 때의 하락폭 (mmWave 입력 오차 대응).

### 5.2 비교군

| 방법 | 재채점 횟수 | 비고 |
|---|---|---|
| 스텁 + 재채점 | 2 | 현재 동작 |
| kNN + 재채점 | n | 가까운 학습 체형 n개의 최적 출력. 학습 없는 기준선 |
| 봉우리 분류 + 봉우리별 회귀 | 2 | `interfaces.md` 우회책, 봉우리마다 후보 1개 |
| flow + 재채점 | n | 제안안 |
| flow + 스텁 + 재채점 | n | 샘플 n − 2개 + 고정 후보 2개 |
| MLP · HGB 평균 회귀, flow1 | 0 | 재채점 없는 참고 |
| Mixture Density Network | n | 가장 단순한 다봉 모델 (후속) |

### 5.3 현재 결과 (#81, 메시판 300행, 체형당 정답 1개, holdout 20체형 × 3, 1,500/m², n = 16)

| 방법 (재채점) | default p05 / <0.95 | pregnant p05 / <0.95 | wheelchair p05 / <0.95 |
|---|---|---|---|
| knn (16) | 0.994 / 0% | 0.998 / 0% | 0.997 / 0% |
| flow+stub (16) | 0.966 / 5% | 0.975 / 5% | 0.964 / 0% |
| flow (16) | 0.956 / 5% | 0.959 / 5% | 0.936 / 30% |
| clsreg (2) | 0.946 / 10% | 0.974 / 5% | 0.994 / 0% |
| stub (2) | 0.907 / 10% | 0.945 / 10% | 0.951 / 5% |
| hgb (0) | 0.894 / 25% | 0.917 / 40% | 0.845 / 65% |
| mlp (0) | 0.847 / 20% | 0.856 / 25% | 0.816 / 55% |
| flow1 (0) | 0.903 / 10% | 0.919 / 15% | 0.858 / 100% |

- 자세만 예측하는 지금은 **kNN이 가장 높다.** 이 조건에서 flow의 이득은 확인되지 않았다.
- flow1 wheelchair가 100% 0.95 미만이다. 샘플이 봉우리 주변으로 퍼져 있다는 신호로 보인다(정답 1개 데이터 + 가우시안 시작 분포). 5.4의 두 실험으로 원인을 가른다.

### 5.4 다음 비교 (순서대로)

1. **후보 여러 개 데이터로 재학습**: `run_dataset.py --candidate-k 16`으로 메시판을 다시 만들고 같은 표를 뽑는다 (공정 비교 조건).
2. **샘플 온도·국소 보정**: 시작 분포 폭을 줄여(σ 0.5~0.7) 샘플을 봉우리에 모으거나, 재채점 최고 후보에서 짧은 국소 탐색(CMA-ES 몇 세대)을 붙인다. 재채점 횟수에 포함해 비교한다.
3. **계획(21차원) E7 데이터셋**이 나오면 같은 스크립트 구조로 kNN · 봉우리 카탈로그 · flow를 비교한다. **최종 채택은 이 비교로 정한다.**

## 6. 리스크와 대응

가장 큰 리스크는 모델이 아니라 라벨이다. 충돌 보정 계수 k가 틀리면 어떤 모델이든 틀린 답을 잘 학습한다.

| 리스크 | 근거 | 대응 |
|---|---|---|
| 라벨이 물리 상수에 흔들림 | E3 메시판: k = 0.5면 세 시나리오 모두 팔 내림으로 바뀌고 regret 31~42%. 계획에서는 T_r·에너지 가중까지 추가 | k 실측 보정 우선. 모델은 `physics_hash`가 바뀌면 무효 |
| 자세 문제에서 kNN보다 못함 | 5.3 | 채택을 계획 E7 비교로 미룸. 자세 추천은 스텁 또는 kNN을 쓰고 flow는 후보 추가용으로만 |
| 데이터 부족 | 메시판 300행, 계획 데이터셋은 100체형 × 3 기준 약 8시간 | 후보 여러 개 저장, 체형 수 확대 |
| 평가 표본이 작음 | holdout 20체형이면 꼬리 지표가 1~2체형으로 결정 | 체형 5-fold로 전 체형 평가 |
| 계획이 장비 제약을 어김 | 샘플은 범위만 지킴 | `PlanEncoder.clip_plan`(풍량 한도, 쾌적 상한, yaw 감기)을 추천 경로에 넣음 |
| 게이트 앞 응답 시간 | 계획 재채점 16개 약 1.3초 | 샘플 수 조정, 재채점 밀도 낮춤 |

| 자리 | 방법 | 하는 일 | 적합도 |
|---|---|---|---|
