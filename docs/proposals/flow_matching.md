# 제안: 회귀 모델 자리에 조건부 Flow Matching 도입

> 2026-09-28 · 제안 문서 (코드 변경 없음). 기준: main `714b63c` (PR #77 병합 시점)

v2의 회귀 모델(체형 → 자세) 자리를 조건부 flow matching 모델로 바꾼다. 최적 자세가 봉우리 여러 개로 갈리는 구조라 회귀보다 flow matching이 잘 맞고, 기존 시뮬레이터·CMA-ES·데이터셋 파이프라인은 그대로 쓴다.

---

## 1. 왜 필요한가

회귀 모델은 봉우리 두 개의 평균을 내서, 점수가 낮거나 부스 밖인 자세를 낼 수 있다. 메시판 데이터셋(300행, `docs/experiments.md`)에서 확인된 구조는 다음과 같다.

| 관찰 | 수치 | 회귀 모델에 주는 문제 |
|---|---|---|
| 팔 벌림 두 봉우리 | 150~180°(만세) 272행, 0~60°(팔 내림) 28행, 60~150° 0행 | 평균 90° 근처 = 데이터에 없는 자세, 부스 밖일 수 있음 |
| yaw 대칭 | +θ ≡ −θ, θ ≡ 180° − θ (0.6533 vs 0.6534) | 접기 없이 학습하면 평균이 0° 또는 90°로 붕괴 |
| 체형에 따른 봉우리 전환 | wheelchair 키 1.45–1.60 m 만세 25%, 1.70–1.80 m 97% | 경계 근처에서 두 봉우리 사이 값 출력 |
| 천장 경계 | 키 1.856 m부터 만세(B2) 불가, 1.86 m는 벌림 163°, 1.93 m는 팔 내림 | 경계 너머에서 불가 자세 출력 |
| 봉우리 점수 차가 작은 경우 | wheelchair 봉우리 차 평균 +0.015 | 두 봉우리 모두 "정답에 가까운 답"인데 하나만 학습 |

`docs/interfaces.md` 회귀 계약도 같은 문제를 적고 "봉우리 분류 → 봉우리 안 회귀"를 우회책으로 둔다. 조건부 flow matching은 p(자세 | 체형, 시나리오)를 분포로 학습하므로 분류 단계 없이 각 봉우리에서 샘플을 낸다.

---

## 2. 어디에 넣나

바뀌는 곳은 **후보 저장, 학습 모델, 추천 단계** 세 곳이다 (`*` 표시).

```
[① 오프라인: 데이터셋 생성]
  체형·시나리오 샘플  →  시뮬레이터 (패치판, 기존)  →  CMA-ES + 후보 저장*
  (메시 체형 분포 × 3)                                  (최고점 2% 이내 후보 여러 개)
                                                              ↓
[② 학습]                                           조건부 flow matching*
                                                    p(자세 | 체형, 시나리오)
                                                    회귀 모델 자리 대체
                                                              ↓ 학습된 모델
[③ 게이트 앞: 실시간 추천]
  체형 추정            →  후보 샘플링·재채점*        →  자세 안내 (기존)
  (카메라 또는 mmWave)     16~32개 뽑아 패치판 채점       최고점 자세를 3D 마네킹으로
```

시뮬레이터와 CMA-ES는 그대로 두고, 저장하는 후보 수와 학습 모델, 게이트 앞 추천 단계만 바뀐다. 체형 입력은 카메라(v2)든 mmWave(추가 계획)든 같은 `BodyParams` 인터페이스로 들어온다.

---

## 3. 설계안

모델은 7차원 출력의 작은 MLP 벡터장 하나다. 입출력 인터페이스는 `predict_pose(body, scenario) -> PoseParams` 계약을 그대로 지킨다.

| 항목 | 내용 |
|---|---|
| 조건 | 체형 5개 + 시나리오 원핫 3개 (mmWave 계획이면 몸무게 등 추가) |
| 출력 | 자세 7개, `PoseEncoder`로 [-1, 1] 정규화 (휠체어는 고정 관절 빼고 5개), yaw는 0~90°로 접은 값 |
| 학습 목표 | conditional flow matching: x_t = (1 − t)·x_0 + t·x_1, 목표 속도 x_1 − x_0를 MSE로 회귀 |
| 시작 분포 x_0 | 가우시안 노이즈. 대안으로 "기본 자세(B0) + 노이즈"에서 출발하면 경로가 짧아져 적분 스텝을 줄일 수 있다. 봉우리가 여러 개라 노이즈는 반드시 남긴다 |
| 데이터 | 체형마다 최적 자세 1개만 두면 사실상 회귀와 같다. CMA-ES가 평가한 후보 중 최고점의 2% 이내인 것을 여러 개 저장해 진짜 분포를 만든다 (두 시작점 default·hands_up의 후보 모두). 추가 계산 없이 행 수가 늘어난다 |
| 추론 | 샘플 16~32개 → `clip_pose` + `outside_booth` 검사 → 패치판 `batch_evaluate`로 재채점 → 최고점 자세 출력 |
| 시간 | ODE 적분 10~20스텝은 수 ms. 재채점은 1,500/m²에서 1회 약 40 ms라 16개면 약 0.6초, 32개면 약 1.3초 |
| 위치 | `airis/model/` (현재 비어 있음), 산출물은 `data/models/`에 `nozzle_layout_hash`·`physics_hash`와 함께 저장 |

재채점 단계가 핵심 이점이다. 모델이 봉우리를 잘못 골라도 시뮬레이터가 최종 선택을 바로잡는다. 현재 `airis/realtime/recommend.py` 스텁이 이미 "E4 결과표의 후보 → `outside_booth` 거르기 → 패치판 재채점"을 하므로, 이 제안은 스텁의 **고정 후보표를 체형별 모델 샘플로 바꾸는 것**이다.

---

## 4. 오해하기 쉬운 점

flow matching이 도움이 되는 이유는 다봉 분포를 다루기 때문이지, 바람의 경로를 학습하기 때문이 아니다.

- **flow는 공기 흐름이 아니다.** flow matching의 flow는 노이즈 분포를 자세 분포로 옮기는 벡터장이다. 노즐에서 나온 바람의 경로는 이미 `airis/sim/jet.py`의 자유 제트 식이 계산한다.
- **이상적인 바람 도달 위치는 미리 정해져 있지 않다.** 노즐이 고정이어도 바람이 몸의 어디에 어떤 각도로 닿는지는 자세가 정한다. 그 자세를 찾는 것이 CMA-ES고, 제거 여부는 도달 위치가 아니라 표면 전단력이 정한다.
- **회귀보다 데이터를 덜 쓰지 않는다.** 같은 CMA-ES 데이터셋이 필요하고, 보통은 더 많이 필요하다. 추론도 ODE 적분이라 회귀보다 느리지만, 7차원이라 수 ms 수준이다.
- **강화학습이나 최적화를 대체하지 않는다.** 라벨은 여전히 시뮬레이터 + CMA-ES가 만든다. README의 "최적화와 학습의 역할 분리" 원칙은 그대로다.

## 5. 검증 계획

기존 E5 지표를 그대로 쓰고, 홀드아웃 체형에서 flow matching이 회귀·MDN 비교군보다 점수 비율이 높으면 채택한다. 점수 비율 = (예측 자세의 시뮬레이터 점수) / (직접 CMA-ES 최적화 점수)다.

| 모델 | 봉우리 처리 | 비고 |
|---|---|---|
| MLPRegressor | 없음 (평균) | README 5.6 계획의 기본안 |
| HistGradientBoostingRegressor | 없음 (평균) | README 5.6 계획의 기본안 |
| 분류 → 봉우리 안 회귀 | 수작업 분류 | `docs/interfaces.md`의 우회책 |
| Mixture Density Network | 가우시안 혼합 | 가장 단순한 다봉 모델 (8절) |
| 조건부 flow matching (재채점 없음) | 분포로 학습 | 샘플 1개만 사용 |
| 조건부 flow matching + 재채점 | 분포로 학습 | 제안안 |

- 지표: 점수 비율의 중앙값과 하위 5%, 부스 밖 자세 비율, 추론 시간
- 채택 기준: 중앙값 0.95 이상(README H3)이고, 하위 5%와 부스 밖 비율이 비교군보다 나을 것
- 집중해서 볼 구간: 휠체어 키 1.45–1.60 m, 선 자세 키 1.83 m 이상 (봉우리 전환·천장 경계)
- 추가: 체형에 ±5% 오차를 넣었을 때의 점수 하락폭 (E5 계획 항목, mmWave 입력 오차 대응)

발표에서는 이 비교표 자체가 "회귀 vs 생성 모델" 실험 하나가 된다.

## 6. 리스크와 대응

가장 큰 리스크는 모델이 아니라 라벨이다. 충돌 보정 계수 k가 틀리면 어떤 모델이든 틀린 답을 잘 학습한다.

| 리스크 | 근거 | 대응 |
|---|---|---|
| 라벨이 물리 상수에 흔들림 | E3 메시판: k = 0.5면 세 시나리오 모두 팔 내림으로 바뀌고 regret 31~42% | k 실측 보정을 우선 유지. 모델은 `physics_hash`가 바뀌면 무효 처리 |
| 데이터 부족 | 메시판 데이터셋 300행 (계획 4,500행) | 체형당 후보 여러 개 저장, 체형 수 확대. 작은 MLP와 조기 종료로 과적합 관리 |
| 샘플이 부스 밖 | 만세 자세는 천장 2.15 m에 가까움 | `clip_pose` + `outside_booth` 검사 후 재채점으로 탈락 |
| 게이트 앞 응답 시간 | 재채점 32개 약 1.3초 | 샘플 수를 16개로 줄이거나, 재채점은 400/m²로 낮춰 사용 |
| 회귀와 차이가 작음 | 선 자세는 98~99%가 만세라 다봉이 거의 없음 | 차이는 휠체어·키 경계 구간에서 나올 것. 이 구간을 따로 보고 |

## 8. 지금까지 시도한 것과 후속 후보

v2에서 실제로 돌린 방법은 최적화(CMA-ES)와 시뮬레이터 변형뿐이고, 학습 모델은 아직 없다.

| 영역 | 시도한 것 | 상태 |
|---|---|---|
| 최적화 | CMA-ES (두 시작점 default·hands_up, 시드 5개) | E4·E3·데이터셋 완료 |
| 기준선 | B0 기본 자세, B1 몸 회전 12방향 평균, B2 만세 | 완료 |
| 평가기 | 패치판 vs 입자판 | E2 ρ 0.97~0.98, 패치판을 대체재로 채택 |
| 몸 모델 | 캡슐 → MakeHuman 메시 | E5 후 메시로 전환 |
| 물리 변형 | 노즐 원형 16 → 슬롯 12, 충돌 보정, 거칠기, 패치 밀도 | E3 민감도 |
| 학습 모델 | 없음 (`airis/model/` 비어 있음) | 미구현 |
| 실시간 추천 | 스텁: 고정 후보표 → 부스 밖 확인 → 패치판 재채점 | 동작 중 |
| 강화학습 | 설계 단계에서 제외 (정적 자세) | 시도 안 함 |
| LBM 검증 (E6) | `validation/lbm/` 비어 있음 | 미실행 |

후속 후보는 들어가는 자리별로 나눈다. 적합도는 현재 문제(자세 7개, 정적, 패치판 1회 약 40 ms, 체형 → 자세 즉시 응답)를 기준으로 했다.

| 자리 | 방법 | 하는 일 | 적합도 |
|---|---|---|---|
| 최적화 | 다목적 최적화 (NSGA-II, MO-CMA-ES) | 제거율과 불편도를 λ로 합치지 않고 Pareto 곡선으로 제시. E3의 불편도 가중 민감도와 임산부 편의 문제에 직접 답함 | 높음 |
| 최적화 | Quality-Diversity (MAP-Elites) | 팔 벌림 × yaw 칸마다 최고 자세를 모은 표. 대체 자세 안내와 flow matching용 다봉 데이터를 함께 얻음 | 높음 |
| 최적화 | 베이지안 최적화 (GP, TuRBO) | 평가가 비쌀 때. 패치판은 CMA-ES로 충분하고, LBM(1회 2~10초) 위 직접 최적화(E6)에 맞음 | 중간 |
| 최적화 | Contextual 최적화 | 체형을 조건으로 한 번에 최적화해 체형별 개별 실행을 줄임 | 중간 |
| 학습 | Mixture Density Network | 가장 단순한 다봉 모델. 가우시안 2~3개로 두 봉우리를 잡음. 데이터가 적으면 flow matching보다 나을 수 있어 **비교군에 포함** | 높음 |
| 학습 | 조건부 flow matching | 이 문서의 제안. 출력이 늘어나는 확장(작동시간·운전모드)에 유리 | 높음 |
| 학습 | 점수 surrogate f(체형, 자세) → 점수 | 게이트 앞에서 경사 상승 또는 샘플 재채점에 사용 | 중간 |
| 학습 | Diffusion (DDPM) | flow matching과 같은 계열이고 더 복잡해 따로 할 이유 없음 | 낮음 |
| 제어 | 강화학습 | 정적 자세에서는 contextual bandit이 되어 CMA-ES보다 비효율. 노즐 시간 제어(펄스·구간별 세기, README 12절)나 통과 중 자세 순서를 다룰 때만 검토. 그때도 "스케줄 파라미터화 + CMA-ES" 기준선을 먼저 둠 | 확장 시에만 |
| 물리 | 베이지안 보정 | 형광 분말·풍속계 측정으로 k 등 상수 추정. E3의 최대 리스크(k)에 직접 대응 | 높음 (실측 가능 시) |
| 물리 | 미분 가능 시뮬레이션 | Taichi 자동 미분. 입자판은 임계값 판정이 불연속이라 매끄럽게 만든 패치판에서만 가능 | 낮음~중간 |
| 물리 | Neural operator (FNO) | LBM 유동장 대체. 6주 일정에는 부담 | 낮음 |

추천 순서는 다음과 같다.

1. MDN + flow matching 비교 (이 제안 범위, 비용 최소)
2. 다목적 최적화로 Pareto 곡선 (E3 불편도 민감도 대응, 발표 그림)
3. MAP-Elites (대체 자세 안내 + 다봉 데이터)
4. LBM 위 베이지안 최적화 (E6 여력이 있을 때)
5. 강화학습은 노즐 시간 제어를 채택할 때만
