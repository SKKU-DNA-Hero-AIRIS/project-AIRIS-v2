## 2. 왜 바꾸나

현재 제목은 v2 첫 계획(자세 7개만 최적화)을 기준으로 붙었다. 그 뒤로 범위가 두 번 넓어졌다.

1. **세기·시간 확장 (`docs/plan_extension.md`, 2026-09-29 확정)**: 최적화 대상이 자세에서 **자세 순서 + 구역 세기 + 분사 시간**(계획, 21차원)으로 넓어졌다. "장치가 사람에게 맞춘다"는 README 1절의 문장이 이제 실제 결정 변수다. "최적 자세를 찾는다"는 제목은 이 절반을 빠뜨린다.
2. **혼합 추천 (트랙 F, 2026-09-30 확정)**: 실시간 응답은 회귀 한 번이 아니라 **AI가 후보를 내고(flow 샘플·kNN) 시뮬레이터가 다시 채점해 고르는** 구조다. AI 와 물리가 역할을 나눠 맞물리는 것이 이 시스템의 핵심인데 현재 제목에는 AI 가 없다.

제안 제목의 각 단어가 이미 있는 구성 요소에 일대일로 대응한다.

| 제목의 말 | v2 의 실체 | 위치 |
|---|---|---|
| 체형 | `BodyParams` 5개, 카메라 키포인트로 추정 | `airis/realtime/pose_estimate.py`, `airis/sim/human_mesh.py` |
| 사용자 특성 | 시나리오(일반·임산부·휠체어)의 자세 범위·불편도 가중·고정 자세·구역 쾌적 상한 | `configs/scenarios.yaml` |
| 물리 시뮬레이션 | 패치판(닫힌 식) · 입자판(Taichi GPU), 충돌 보정 k 1.4, 시간 의존 제거 | `airis/sim/` |
| AI 융합 | flow matching + kNN 후보 → 시뮬레이터 재채점 (AI 가 제안, 물리가 판정) | `airis/model/`, `airis/realtime/recommend.py` |
| 사용자 맞춤형 최적화 | CMA-ES 로 체형·시나리오별 자세(E4)·계획(E7) | `airis/optimize/` |
| 에어게이트 (시스템) | 단계별 안내 화면 + 노즐 12개 장비 제어 출력 | `scripts/run_dashboard.py`, `airis/realtime/plan_guide.py` |

## 3. 바꾸지 않는 것

- 연구 질문 Q1~Q5, 가설 H1~H3, 실험 번호 E1~E7, 계산 예산.
- **결론은 절대값이 아니라 기준 대비 상대 개선율과 상수에 견고한 순위로 말한다** (README 1절 원칙).
- 시나리오(임산부·휠체어)는 영상으로 판별하지 않고 사용자가 고른다. "사용자 특성"이 카메라 추정을 뜻하지 않는다.
