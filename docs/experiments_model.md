# 추천 모델 실험 기록 (트랙 F)

소유자: F. 체형 → 자세·계획 추천 모델의 비교·인수 확인·갱신 기록이다. 최적화·데이터셋 실험은 트랙 C의
`docs/experiments.md`에 있다. 모델 역할과 단계는 `docs/tracks/F_model.md`.

**점수 비율** = 추천 자세 점수 / 그 체형을 직접 최적화한 점수(데이터셋 `score`). 두 점수는 같은 평가기
(학습 데이터의 몸 모델·패치 밀도, `predict.default_rescorer`)로 잰다.

**합격 기준** (혼합 추천, 체형 5-fold, 시나리오 합산): 하위 5% ≥ 0.99, 0.95 미만 ≤ 2%, 불가 0, 평균 응답 ≤ 1.5 s.
중앙값은 쓰지 않는다(고정 후보표만으로도 0.997이다).

## 3. 산출물 갱신 절차

물리 기준(`configs/physics.yaml`의 계수 k 등)이 바뀌면 두 산출물(flow `pose_flow.pt`, kNN 표 `pose_knn.parquet`)은
무효다. 로드할 때 도장(`nozzle_layout_hash`, `physics_hash`)이 지금 설정과 다르면 `predict`가 경고만 하고 그대로 쓰므로,
물리 값이 바뀌면 아래 순서로 다시 만든다.

1. **데이터셋 재생성 (트랙 C)**: `docs/experiments.md` 데이터셋 절의 명령. 메시판 300행 수 시간.
2. **학습·표·5-fold·판정·설치 (트랙 F, 한 명령)**

   ```bash
   python scripts/train_pose_models.py --dataset data/datasets/<새 데이터셋>.parquet
   ```

   - flow 학습(약 25 s) → kNN 표(1 s 미만) → 체형 5-fold(약 25분, CPU) → 합격 판정 → 합격이면 설치.
   - 산출물은 먼저 `outputs/refresh_<시각>/`에 만들고, **합격했을 때만** 설치 폴더(`data/models/` 또는
     환경변수 `AIRIS_MODEL_DIR`)로 설치한다. 기존 산출물은 `<이름>.prev`로 남긴다(1세대, flow·kNN 쌍).
   - 설치는 준비(`.new`·`.prev.new` 복사) → 교체(`os.replace`, 실패하면 바뀐 파일을 되돌림) → `.prev` 확정 순이다.
     한 번의 실패(복사 중단, 파일 잠김, Ctrl+C)로는 새 flow + 옛 kNN 이 섞인 채 남지 않고 옛 산출물도 잃지 않는다.
     되돌리기까지 실패하는 이중 실패에서는 옛 산출물 백업(`<이름>.prev.new`)을 남기고 `InstallRollbackError`로 알린다.
   - **이중 실패 뒤 복구**: 설치 폴더에 `<이름>.prev.new`가 있으면 다음 설치는 덮어쓰지 않고 멈춘다. 각 `<이름>.prev.new`를
     `<이름>`으로 되돌려(옛 쌍으로 복구) 또는 지금 파일이 맞으면 지워 쌍을 맞춘 뒤 다시 돌린다.
   - 설치가 실패하거나 Ctrl+C 로 끊겨도 `gate.json`에 `install_error`와 설치 폴더의 실제 상태(`install_state`: 파일마다
     이번 산출물과 같으면 new, 아니면 old, 없으면 missing)를 남긴다. 실패면 종료 코드 1, Ctrl+C 는 기록 뒤 다시 올린다.
   - **설치 전에 본 폴더 `data/models`를 여는 프로세스(E 대시보드)를 내린다.** 통합 관리 세션에 "설치 시작"을
     알리고 확인을 받은 뒤 설치한다.
   - 결과: `e5cv.csv`(행별), `e5cv_overall.csv`(방법별 전체 지표), `gate.json`(판정·도장·시간),
     `gate.md`(이 문서 2절에 붙일 표). 불합격이면 종료 코드 1.
   - 선택: `--no-install`(재현만), `--skip-cv --install`(판정 없이 설치, 급할 때), `--folds 2 --limit 2 --no-install`
     (빠른 점검, 약 1.5분, 판정 무효).
3. **기록**: `gate.md`를 2절에 붙이고, 통합 관리 세션에 결과를 알린다(E가 화면 연결에 쓰는 산출물이 바뀐다).

worktree에서 돌릴 때는 데이터셋 경로를 본 폴더로 주고, 설치 폴더를 `--model-dir`(또는 `AIRIS_MODEL_DIR`)로
본 폴더 `data/models`에 맞춘다.

도장 규약: `physics_hash`·`nozzle_layout_hash`는 C의 `explog.file_hash`로, #98(2026-09-30)부터 **YAML 파싱 내용을
정렬 직렬화(JSON, sort_keys)한 뒤 sha256** 한 값이다(주석·줄바꿈·키 순서 무관, YAML 이 아닌 파일은 바이트 해시).
그 전에는 파일 바이트 전체의 sha256이라 물리 값이 같아도 키 추가(#88)나 줄바꿈으로 바뀌었다(예: 커밋 `798b0f1`의
같은 파일이 CRLF 체크아웃 `e9a97f3c`, LF `0964e244`). 옛 규약으로 만든 산출물·기준 행(2.1)의 도장은 새 규약과
비교하면 전부 불일치로 나오며, k 1.4 재생성으로 해소된다. `predict.current_stamp`·`stamp_mismatch`가 판정 기준이고
로드 경고·갱신 명령·`artifact_status`(E 대시보드)가 모두 이것을 쓴다.

## 4. 계획 모델

- `predict_plan`은 flow 샘플과 고정 계획을 전부 C의 `PlanEncoder.clip_plan`(자세·시간·구역 세기, 쾌적 상한,
  풍량 한도 보수)으로 투영한 뒤 채점한다. 범위는 `physics.yaml`의 `plan.*`·`fan.*`, 풍량 한도의 구역별 노즐 수는
  실제 장비 구성 `airis.sim.scenario.zone_nozzle_counts()`([2, 2, 2, 2, 4], C의 계획 데이터셋과 같음).
- 계획 재채점기(`default_rescorer(model, plan=True)`)는 C의 `plan_physics_cfg()`(시간 의존 제거 kinetics 켬)를 쓴다.
  계획 데이터셋도 같은 함수로 만든다. 자세 재채점은 설정 파일 그대로다(kinetics 는 계획 평가에만 적용).
- 계획 산출물의 도장에는 `kinetics_enabled`·`time_constant_s`(C의 `plan_kinetics_stamp`)도 들어가고, 로드할 때
  지금 계획 설정과 비교한다. 자세 산출물에는 이 키가 없어 비교하지 않는다. 계획 모델 학습 스크립트를 만들 때
  데이터셋의 이 두 열을 meta 에 옮긴다.
- `PlanSpace`(F)와 `PlanEncoder`(C)의 규격 대조는 `tests/test_model_plan_spec.py`: 같은 설정에서 읽은 범위,
  K = 1~3 단계 시간 식, normalize·clip 뒤 계획이 `PlanSpace` 범위 안인지, 원래 단위 벡터가 같은지,
  to_plan 뒤 clip이 쾌적 상한·풍량 한도만 바꾸는지.
- 비교(혼합·flow·kNN·고정 계획표·국소 탐색)는 계획 데이터셋이 나온 뒤에 한다.

## 5. 재채점 단축 (총괄 2026-09-30)

혼합 추천의 응답 시간이 E 화면 밀도(메시 2,000/m²)에서 1.3~2.0 s로 목표 1.5 s를 넘는다(E 실측). 총괄 결정: 지금은
화면 경고만 두고, k 1.4 5-fold 때 아래 조합을 현 구성과 나란히 재서 구성을 확정한다. 후보 수를 5+5로 줄이는 안은 쓰지 않는다.

| 안 | `predict` 옵션 | 내용 |
|---|---|---|
| R0 | (기본) | flow 8 + kNN 8 + 고정 2 전부 최종 밀도로 재채점 |
| A | `dedup_deg=3` | 관절 각도 차 최대값 3° 이하(yaw 는 접은 값)인 flow·kNN 후보를 하나로. 고정 후보는 전부 남김 |
| B | A + `screen_density=400, screen_top=4` | 모든 후보를 400/m²로 선별, 상위 4개만 최종 밀도로 |
| C | A + `screen_density=800, screen_top=3` | 800/m²로 선별, 상위 3개 |
| D | A + `n_threads=3` | 재채점을 스레드 3개로. 고르는 자세는 A 와 같다(테스트로 고정), 시간만 다르다 |

- 품질(점수 비율)은 데이터셋 밀도(1,500/m²)로 `run_e5_flow.py --methods hybrid,hybrid-a,hybrid-b,hybrid-c`
  5-fold에서 잰다. D 는 A 와 결과가 같아 품질 측정에서 뺀다.
- 응답 시간은 CPU 가 비어 있을 때 `run_e5_timing.py`로 잰다: `--bench`(밀도별 1회 비용), 그리고 2,000/m² 체형
  30개 표본에서 R0·A·B·C·D (첫 호출 제외, 방법 순서를 돌려 가며).
- 밀도별 1회 비용에서 고정비(자세별 메시 변형·가림 준비)가 지배하면 B·C 는 빼고 그 사실을 표에 적는다.
  D 실측(400/m² 1회): build_body 21.7 ms + 가림 11.5 ms + 제트 4.5 ms.
- 선별을 켜면 `Prediction.scores`는 최종 채점한 후보만 값이 있고 나머지는 NaN 이다. E 가 선별을 쓰게 되면
  출처별 최고 점수 계산을 이에 맞춰야 한다.

고정비(밀도와 무관한 부분, 선형 외삽 약 15 ms)가 있지만 밀도 비중이 커서 저밀도 선별(B·C)에도 이득이 있다.
그래서 B·C 를 뺄 조건(고정비 지배)에 해당하지 않는다. 재부팅 전 CPU 혼잡 중 본 비율(0.71)은 부하 탓이었다.

응답 시간 (`run_e5_timing.py`, 최종 2,000/m², 데이터셋 30행 = 체형 26개, 방법 순서를 돌려 가며, 첫 호출 제외)

| 안 | 평균 | 95% | 후보(중복 제거 뒤) | 최종 재채점 수 |
|---|---|---|---|---|
| R0 현 구성 | 1.05 s | 1.50 s | 18 | 18 |
| A 중복 제거 3° | 0.83 s | 1.20 s | 13.9 | 13.9 |
| B A + 400/m² 선별 상위 4 | 0.59 s | 0.77 s | 13.9 | 4 |
| C A + 800/m² 선별 상위 3 | 0.63 s | 0.84 s | 13.9 | 3 |
| D A + 스레드 3 | 0.58 s | 0.83 s | 13.9 | 13.9 |

- CPU 가 비어 있으면 현 구성도 평균 1.05 s 로 기준(1.5 s) 안이지만 95% 가 1.50 s 로 경계다. E 실측 1.3~2.0 s 는
  CPU 혼잡의 영향이 컸던 것으로 보인다.
- 중복 제거만으로 후보가 평균 4.1개(23%) 줄고 21% 빨라진다.
- B·C·D 는 모두 평균 약 0.6 s, 95% 0.85 s 이하. D 는 고르는 자세가 A 와 같다(테스트로 고정). B·C 는 선별로 품질이
  떨어질 수 있어 k 1.4 데이터셋 5-fold 로 확인한다. B + D(선별 + 스레드) 조합은 재지 않았다.

### 5.2 품질 (k 1.4 데이터셋 5-fold 와 함께, 대기)

잴 것 (통합·총괄 요청 2026-10-01):
- 품질(데이터셋 밀도 1,500/m², 체형 5-fold): R0·A·B·C 의 하위 5%, 0.95 미만, 불가.
  `train_pose_models.py --methods hybrid,hybrid-a,hybrid-b,hybrid-c,knn+stub,flow+stub,stub`.
- **A 의 중복 제거가 품질에 주는 영향을 따로 적는다**: 3° 안의 후보를 "먼저 나온 것"으로 남기므로, 근접 후보 중 점수가
  더 높은 쪽을 버릴 수 있다. R0 와 A 가 고른 자세가 다른 행의 수와 점수 비율 차이를 표에 넣는다.
- 응답 시간(CPU 빈 상태, 2,000/m²): A + D(`hybrid-d`)와 B + D(`hybrid-e`, 선별 + 스레드)를 5.1 과 같은 방식으로.
- 통합 의견: 품질이 보장되는 A + D 가 기본 후보이고, B·C 는 품질 손실이 없을 때만 추가 이득으로 채택한다.
  구성 확정은 총괄.
