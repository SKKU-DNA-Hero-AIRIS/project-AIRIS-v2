# 추천 모델 실험 기록 (트랙 F)

소유자: F. 체형 → 자세·계획 추천 모델의 비교·인수 확인·갱신 기록이다. 최적화·데이터셋 실험은 트랙 C의
`docs/experiments.md`에 있다. 모델 역할과 단계는 `docs/tracks/F_model.md`.

**점수 비율** = 추천 자세 점수 / 그 체형을 직접 최적화한 점수(데이터셋 `score`). 두 점수는 같은 평가기
(학습 데이터의 몸 모델·패치 밀도, `predict.default_rescorer`)로 잰다.

**합격 기준** (혼합 추천, 체형 5-fold, 시나리오 합산): 하위 5% ≥ 0.99, 0.95 미만 ≤ 2%, 불가 0, 평균 응답 ≤ 1.5 s.
중앙값은 쓰지 않는다(고정 후보표만으로도 0.997이다).

## 3. 산출물 갱신 절차

물리 기준(`configs/physics.yaml`의 계수 k 등)이 바뀌면 두 산출물(flow `pose_flow.pt`, kNN 표 `pose_knn.parquet`)은
무효다. 로드할 때 도장(`nozzle_layout_hash`, `physics_hash`)이 지금 설정과 다르면 `predict`가 경고만 하고 그대로 쓰므로,
물리 값이 바뀌면 아래 순서로 다시 만든다.

1. **데이터셋 재생성 (트랙 C)**: `docs/experiments.md` 데이터셋 절의 명령. 메시판 300행 수 시간.
2. **학습·표·5-fold·판정·설치 (트랙 F, 한 명령)**

   ```bash
   python scripts/train_pose_models.py --dataset data/datasets/<새 데이터셋>.parquet
   ```

   - flow 학습(약 25 s) → kNN 표(1 s 미만) → 체형 5-fold(약 25분, CPU) → 합격 판정 → 합격이면 설치.
   - 산출물은 먼저 `outputs/refresh_<시각>/`에 만들고, **합격했을 때만** 설치 폴더(`data/models/` 또는
     환경변수 `AIRIS_MODEL_DIR`)로 설치한다. 기존 산출물은 `<이름>.prev`로 남긴다(1세대, flow·kNN 쌍).
   - 설치는 준비(`.new`·`.prev.new` 복사) → 교체(`os.replace`, 실패하면 바뀐 파일을 되돌림) → `.prev` 확정 순이다.
     한 번의 실패(복사 중단, 파일 잠김, Ctrl+C)로는 새 flow + 옛 kNN 이 섞인 채 남지 않고 옛 산출물도 잃지 않는다.
     되돌리기까지 실패하는 이중 실패에서는 옛 산출물 백업(`<이름>.prev.new`)을 남기고 `InstallRollbackError`로 알린다.
   - **이중 실패 뒤 복구**: 설치 폴더에 `<이름>.prev.new`가 있으면 다음 설치는 덮어쓰지 않고 멈춘다. 각 `<이름>.prev.new`를
     `<이름>`으로 되돌려(옛 쌍으로 복구) 또는 지금 파일이 맞으면 지워 쌍을 맞춘 뒤 다시 돌린다.
   - 설치가 실패하거나 Ctrl+C 로 끊겨도 `gate.json`에 `install_error`와 설치 폴더의 실제 상태(`install_state`: 파일마다
     이번 산출물과 같으면 new, 아니면 old, 없으면 missing)를 남긴다. 실패면 종료 코드 1, Ctrl+C 는 기록 뒤 다시 올린다.
   - **설치 전에 본 폴더 `data/models`를 여는 프로세스(E 대시보드)를 내린다.** 통합 관리 세션에 "설치 시작"을
     알리고 확인을 받은 뒤 설치한다.
   - 결과: `e5cv.csv`(행별), `e5cv_overall.csv`(방법별 전체 지표), `gate.json`(판정·도장·시간),
     `gate.md`(이 문서 2절에 붙일 표). 불합격이면 종료 코드 1.
   - 선택: `--no-install`(재현만), `--skip-cv --install`(판정 없이 설치, 급할 때), `--folds 2 --limit 2 --no-install`
     (빠른 점검, 약 1.5분, 판정 무효).
   - **5-fold 와 설치를 나눠 할 때**: `--no-install` 로 돌려 결과를 확인하고, 대시보드를 내린 뒤
     `python scripts/train_pose_models.py --install-from outputs/<결과 폴더> --model-dir <설치 폴더>` 로 설치만 한다.
     그 폴더 `gate.json` 의 판정이 합격일 때만 설치하고, 설치 결과(시각 포함)를 같은 `gate.json` 에 덧붙인다.
   - `gate.json`·`gate.md` 의 커밋은 **시작할 때의** 커밋이다. 실행 중에는 같은 작업 폴더에서 커밋·병합을 하지 않는
     편이 낫다(돌고 있는 코드는 시작할 때 읽은 것이다).
3. **기록**: `gate.md`를 2절에 붙이고, 통합 관리 세션에 결과를 알린다(E가 화면 연결에 쓰는 산출물이 바뀐다).

worktree에서 돌릴 때는 데이터셋 경로를 본 폴더로 주고, 설치 폴더를 `--model-dir`(또는 `AIRIS_MODEL_DIR`)로
본 폴더 `data/models`에 맞춘다.

도장 규약: `physics_hash`·`nozzle_layout_hash`는 C의 `explog.file_hash`로, #98(2026-09-30)부터 **YAML 파싱 내용을
정렬 직렬화(JSON, sort_keys)한 뒤 sha256** 한 값이다(주석·줄바꿈·키 순서 무관, YAML 이 아닌 파일은 바이트 해시).
그 전에는 파일 바이트 전체의 sha256이라 물리 값이 같아도 키 추가(#88)나 줄바꿈으로 바뀌었다(예: 커밋 `798b0f1`의
같은 파일이 CRLF 체크아웃 `e9a97f3c`, LF `0964e244`). 옛 규약으로 만든 산출물·기준 행(2.1)의 도장은 새 규약과
비교하면 전부 불일치로 나오며, k 1.4 재생성으로 해소된다. `predict.current_stamp`·`stamp_mismatch`가 판정 기준이고
로드 경고·갱신 명령·`artifact_status`(E 대시보드)가 모두 이것을 쓴다.

## 4. 계획 모델

- `predict_plan`은 flow 샘플과 고정 계획을 전부 C의 `PlanEncoder.clip_plan`(자세·시간·구역 세기, 쾌적 상한,
  풍량 한도 보수)으로 투영한 뒤 채점한다. 범위는 `physics.yaml`의 `plan.*`·`fan.*`, 풍량 한도의 구역별 노즐 수는
  실제 장비 구성 `airis.sim.scenario.zone_nozzle_counts()`([2, 2, 2, 2, 4], C의 계획 데이터셋과 같음).
- 계획 재채점기(`default_rescorer(model, plan=True)`)는 C의 `plan_physics_cfg()`(시간 의존 제거 kinetics 켬)를 쓴다.
  계획 데이터셋도 같은 함수로 만든다. 자세 재채점은 설정 파일 그대로다(kinetics 는 계획 평가에만 적용).

#111 검토에서 확인된 사실 (2026-10-01, 표 설계에 반영):
- **중복 제거(A)는 표(고정 후보)보다 나빠지지 않지만 R0 보다는 나빠질 수 있다.** 고정 후보는 절대 빼지 않고 앞쪽
  flow·kNN 후보를 뺀다. 3° 안에서도 점수가 크게 바뀌는 자세가 있다(만세 yaw 20° → 23°에 0.3095 → 0.3339).
  실측 예: 체형 0·wheelchair 0.38664 → 0.38611. 그래서 5-fold 에서 **A 를 R0 와 나란히** 보고, 각도 1°·2°·3°
  (`hybrid-a1`·`hybrid-a2`·`hybrid-a`)를 함께 잰다.
- **선별(B·C)을 켜면 표보다 나빠질 수 있다.** 실측 체형 0·default: R0 0.62850(표 후보) → B 0.62622(kNN).
  400/m² 선별에서 표 후보 2개가 모두 탈락했다. 대안 `screen_keep_extra=True`(`hybrid-bx`)는 고정 후보를 선별과
  상관없이 최종 채점에 넣어(재채점 +2) 표 보장을 유지한다. 5-fold 표에 이 행을 넣는다.
- 선별 상위가 최종 밀도에서 전부 불가면 나머지 후보를 **전부** 최종 채점해 그중 최고를 고른다(불가 추천 방지,
  #111 후속). 이 경우 선별 채점(전 후보) + 최종 채점(전 후보)이라 **비용이 R0 보다 커진다**. 큰 체형에서 만세가
  천장에 걸릴 때처럼 드문 경우이지만 95% 응답에는 잡힐 수 있어, 5-fold 표에 폴백이 걸린 행 수를 적는다.
- 스레드 채점은 패치판처럼 `batch_evaluate` 를 재정의하지 않은 평가기 전용이다. 입자판에서는 경고 후 순차 채점.

(스레드 변형 D·E 는 고르는 자세가 A·B 와 같아 품질에서는 빼고 시간만 잰다).

| E 변경 최소 | 인자 두 개만 넘긴다. 점수에 NaN 이 생기지 않아 출처별 통계를 그대로 쓰고, 선별 평가기가 필요 없다 |

- `predict` 의 기본값은 바꾸지 않았다(기본 = R0). 5-fold 합격 판정과 기존 수치의 기준이 R0 이기 때문이고,
  확정 구성은 호출하는 쪽(E 의 `recommend`)이 인자로 넘긴다.
- **대안 F(BX + 스레드, `screen_density=400, screen_top=4, screen_keep_extra=True, n_threads=3`)**: 품질은 D 와 같고
  평균 7%, 95% 17% 더 빠르다. 대신 E 가 자기 몸 모델의 400/m² 선별 평가기(`screen_evaluator`)를 넘기고 NaN 점수를
  처리해야 한다. 더 느린 장비나 재채점 밀도 상향으로 여유가 줄면 F 로 넘어간다.
- 스레드 3개는 D 확인(1.6~1.7배에서 포화)에 따른 값이다. 스레드 채점은 패치판 전용이다.

### 6.1 fold 규칙 (`run_e5_flow.py --fold-rule`)

| 규칙 | 정의 | 쓰는 곳 |
|---|---|---|
| `permutation` (기본) | 시드 순열을 K 조각으로 | 1·2·5절의 모든 기존 수치. 기본값이라 재현이 유지된다 |
| `modulo` | fold = (body_idx + seed) % K | 학습 곡선의 cv 설계. 체형을 늘려도 같은 체형이 같은 fold 에 남는다 |

두 규칙의 수치는 서로 비교하지 않는다(분할이 다르다).

### 6.2 평가 집합 설계

| | cv (팀원 방식) | holdout (권장) |
|---|---|---|
| 평가 집합 | 크기 N 마다 그 N 체형 전부를 5-fold | 번호가 가장 큰 200체형(600행)을 모든 크기가 공통으로 |
| 크기 간 비교 | 평가 체형이 크기마다 다르다. 차이에 평가 집합 차이가 섞인다 | 같은 체형이라 행 단위로 짝지어 비교할 수 있다 |
| 하위 5% 의 꼬리 | N=100 이면 300행 중 15행(잡음 큼), N=1,000 이면 150행 | 어느 크기든 600행 중 30행 |
| 학습 체형 뽑기 잡음 | fold 5개가 평균해 준다 | 작은 크기에서 `--repeats` 로 다르게 뽑아 따로 본다 |
| 쓸 수 있는 최대 학습 크기 | 1,000 (fold 당 800 으로 학습) | 800 |
| flow 학습 횟수 (100·300·600·1,000 / 100·300·600·800) | 24회 (크기마다 기본 1 + fold 5) | 4회, 반복 3회씩(100·300)이면 8회 |
| 평가 행 수 | 6,000행 | 2,400행, 반복 포함 4,800행 |
| 예상 시간 (행당 3방법 약 2 s, 학습 30 s) | 약 3.5시간 | 약 1.4시간, 반복 포함 약 2.7시간 |

권장은 holdout 이다. 이 실험의 물음이 "크기를 늘리면 좋아지는가"이므로 크기 간 비교가 공정해야 하고, 가장 작은
크기에서 꼬리 지표(하위 5%)가 잡음에 묻히지 않아야 한다. 비용도 반복 없이는 절반 이하이고 반복을 넣어도 더 싸다.
행당 2 s 는 k = 1 재현(2.1절, 300행 × 4방법 20분)에서 잡은 값이라 다른 실행과 겹치면 더 걸린다. 약점은 최대 학습 크기가 800 으로
줄고 결과가 평가 200체형 한 벌에 묶인다는 점이다. 최종 선택은 총괄이 한다(스크립트는 둘 다 지원).

## 7. 체형 입력 오차 내성 (총괄 2026-10-04)

물음: 카메라 포즈 추정이 체형 값을 틀리게 주면(외투·조명) 추천 품질이 얼마나 떨어지는가. 입력 센서를 바꿀지
(mmWave 등) 판단하는 근거로 쓴다.

방법 (`scripts/run_e5_body_noise.py`, 체형 5-fold 와 같은 틀·같은 fold 분할):
1. fold 마다 학습 체형으로 flow 를 학습하고 kNN 표를 만든다. 오차 수준과 무관하게 한 번만 한다.
2. 평가 체형마다 체형 값 5개(키, 어깨 폭, 몸통 두께, 팔 길이, 다리 길이 = 고관절 높이)에 독립으로 (1 + U(−p, +p)) 를 곱해
   **추정 체형**을 만든다. p = 0(기준)·2·5·10%. 같은 (시드, 체형, 시나리오, p) 면 같은 추정 체형이다.
3. **추천은 추정 체형으로 한다**: 후보 생성(flow 조건, kNN 이웃)도 재채점도 추정 체형이다. 실제 장비는 진짜 체형을
   모르기 때문이다.
4. **고른 자세는 진짜 체형으로 채점한다.** 점수 비율 = 그 점수 / 진짜 체형의 최적 점수(데이터셋 `score`).
5. 오차 수준마다 하위 5%, 0.95 미만 비율, 불가 비율, 그리고 같은 행끼리 짝지은 비율 변화(평균, 가장 큰 하락,
   추천이 바뀐 행 비율)를 낸다.

불가 비율은 추정 체형에서는 부스 안이던 자세가 진짜 체형에서는 천장·벽에 걸리는 경우를 잡는다(키를 작게
추정하면 만세가 천장에 닿는다). 재채점이 불가 후보를 걸러 주는 안전장치가 체형 오차에서는 뚫릴 수 있는 지점이다.

한계: 오차는 값마다 독립이고 균등 분포다. 실제 추정 오차는 값끼리 상관이 있고(키를 작게 보면 팔도 짧게 본다)
한쪽으로 치우칠 수 있다.

후속 과제(미구현): ① 한쪽으로 치우친 오차(전 체형 값을 같은 방향으로 −p 또는 +p), ② 값끼리 상관된 오차

### 7.2 부스 안 판정 여유 (2026-10-04 20:40~21:56)

7.1절의 제안 1 을 구현하고 쟀다(총괄 승인 2026-10-04). 목표: ±5% 오차에서 **하위 5% ≥ 0.97, 불가 0**.

구현: `predict(..., feasibility_margin=m, feasibility_margin_mode="all" | "reach")`. 기본 `m = 0` 이면 지금 동작
그대로이고 추가 채점도 없다. `m > 0` 이면 점수 순으로 후보를 보며, **키운 몸**에서도 부스 안인 첫 후보를 고른다.
점수와 불가 판정은 추정 체형의 것을 그대로 둔다. 전부 걸리면 여유 없이 고른 후보로 돌아가고 `margin_fallback` 을
켠다. 키우는 값은 방식에 따라 다르다.

| 방식 | 키우는 체형 값 | 뜻 |
|---|---|---|
| `all` | 5개 전부 × (1 + m) | 천장과 벽 모두에 보수적 |

**두 방식의 결과는 행 단위로 완전히 같다.** 여유 0% 의 1,200행이 두 실행에서 같고(재현 검산), 여유 2%·5% 에서도 고른
자세와 점수가 전부 같다. 이 부스(폭 1.46 m)에서는 벽이 걸리지 않기 때문이다: 데이터셋의 최적 자세 300개를
어깨 너비·몸통 두께만 10% 키운 몸으로 채점해도 불가가 0건이고, 5% 키운 몸에서 불가인 30건은 `all` 과 `reach` 가
같은 30건이다. 그래서 아래 표는 두 방식 공통이다.

읽는 법
- **불가 추천은 막는다.** ±5% 오차에서 여유 2% 만으로도 불가가 0 이 된다. 다만 이것은 300행·시드 하나의 결과이고,
  여유가 실제 오차보다 작으면 원리상 뚫릴 수 있다(여유 2% 는 키를 2% 넘게 작게 본 경우를 보장하지 않는다).
  보장하려면 여유를 예상 오차만큼 줘야 한다.
- **하위 5% 목표(≥ 0.97)는 달성하지 못한다.** 여유를 줘도 ±5% 의 하위 5% 는 오르지 않는다(0.9664 → 0.9637 → 0.8505).
  꼬리를 끌어내리는 것은 불가 추천이 아니라 "체형이 틀려 다른 봉우리를 고르는" 경우이고(7.1절, 휠체어), 판정
  여유는 이것을 고치지 못한다. 이 목표는 체형 추정을 정확하게 하는 쪽에서 풀어야 한다.
- **여유는 키 큰 사람의 품질을 깎는다.** 오차가 없어도 여유 5% 면 키 1.75 m 이상인 29행(약 10%)에서 만세가
  걸러져 평균 9.8% 떨어지고, 하위 5% 가 0.993 → 0.909 가 된다. 여유 2% 는 키 1.80 m 이상 9행(3%)에서 평균 3.8% 다.
  휠체어는 영향이 없다(앉은 자세는 천장에 닿지 않는다).
- 추가 비용은 채점 1.2회(2%) ~ 2.1회(5%)다. 응답 시간으로 약 0.06 ~ 0.1 s (2,000/m² 1회 50 ms).
- 폴백(전부 걸려 여유 없이 고른 것으로 돌아감)은 0행이다.

권장 (기본값 결정은 총괄)
- `predict` 의 기본값은 0 으로 둔다(5-fold 합격 판정과 기존 수치의 기준).
- 실제 장비에서는 **방식 `reach`, 여유 = 카메라 키 추정의 예상 오차**로 넘기는 것을 권한다. 이 부스에서는 `all` 과
  결과가 같지만, `reach` 가 뜻이 분명하고(천장) 더 좁은 부스에서도 벽 쪽 품질을 깎지 않는다.
- 예상 오차를 모르는 지금은 **2%** 가 무난하다: 불가 0, 비용은 키 1.80 m 이상 사용자 3% 에 한정. 5% 는 비용이 크다
  (10% 사용자, 하위 5% 0.909). 카메라 체형 오차를 실제로 잰 뒤(E) 값을 정하는 것이 맞다.
- 후속 과제(미구현): 불가 후보를 버리는 대신 **자세를 고쳐 쓰기**(예: 팔을 덜 올린 만세로 낮춰 키운 몸에서도
  천장 아래가 되게). 키 큰 사용자의 손실(−3.8% ~ −9.8%)을 줄일 수 있다.
